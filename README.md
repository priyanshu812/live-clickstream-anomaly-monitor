              (table: window_results, 127.0.0.1:5433)
                    |
                    v

## How it works

### Window features

Each 5-second window is summarised into 5 features:

| Feature | Description |
|---|---|
| `clicks` | Total number of clicks in the window |
| `unique_users` | Number of distinct user IDs |
| `avg_response_ms` | Mean server response time |
| `error_rate` | Fraction of clicks that returned an error |
| `max_user_clicks` | Highest click count from a single user |

### Model

- Algorithm: `IsolationForest(n_estimators=200, contamination=0.06, random_state=42)`
- Trained offline on all 360 windows and saved to `anomaly_model.pkl`
- The live processor only scores incoming windows; it never retrains

### Windowing

- Windows are built from event time (the timestamp inside each click), not wall-clock time
- A window closes when the first click of the next window arrives
- If no click arrives for 5 seconds, the current window is flushed (idle flush)

## Dataset

- 13,496 synthetic clicks generated by `make_data.py`
- 360 windows of 5 seconds each (30 minutes of simulated traffic)
- 22 truly anomalous windows
- Anomaly types: `bot` (single user floods clicks), `spike` (high overall rate), `slow` (high response time and error rate)
- The `label` and `anomaly_type` columns are an answer key and are never shown to the model

## Results

360 windows, 22 truly anomalous.

| contamination | Precision | Recall | F1 |
|---|---|---|---|
| 0.04 | 1.000 | 0.682 | 0.811 |
| **0.06 (final)** | **1.000** | **1.000** | **1.000** |
| 0.10 | 0.611 | 1.000 | 0.759 |

The live pipeline produced 360 windows and 22 flagged windows in PostgreSQL, exactly matching the offline evaluation.

---

## Limitations

- The data is simulated and the anomalies are clear-cut. A real clickstream would be noisier.
- Evaluation was done on the same windows the model was trained on. This does not prove accuracy on unseen data.
- The chosen contamination (0.06) is close to the true anomaly rate (22/360 = 6.1%), which makes the task easier for the model.
- The model flags entire windows, not individual users or clicks.
- Events are assumed to arrive in order. Late events are silently dropped.
- Kafka and PostgreSQL each run as a single Docker container with no replication.

## Setup and run

### Prerequisites

- Python 3.10+
- Docker and Docker Compose

### Steps

1. **Clone the repository**

   ```bash
   git clone <repo-url>
   cd <repo-folder>
   ```

2. **Create a virtual environment and install dependencies**

   ```bash
   python -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   ```

3. **Set up environment variables**

   ```bash
   cp .env.example .env
   ```

   Edit `.env` and set `POSTGRES_PASSWORD` to your chosen password.

4. **Start Kafka and PostgreSQL**

   ```bash
   docker compose up -d
   ```

5. **Generate data and train the model** (skip if `click_data.csv` and `anomaly_model.pkl` are already present)

   ```bash
   python make_data.py
   python train_model.py
   ```

6. **Optional: clear old results**

   ```bash
   docker exec -it pg psql -U monitor -d clickstream -c "TRUNCATE window_results;"
   ```

7. **Terminal 1: start the processor** (must start before the producer, because it reads only new messages)

   ```bash
   python processor.py
   ```

8. **Terminal 2: start the dashboard**

   ```bash
   python -m streamlit run dashboard.py
   ```

   Open [http://localhost:8501](http://localhost:8501) in your browser.

9. **Terminal 3: start the producer**

   ```bash
   python producer.py
   ```

   With the default `SLEEP_PER_SECOND = 0.4`, the full dataset replays in about 12 minutes.
   Set it to `0.05` to finish in about 90 seconds.

10. **Verify the final counts**

    ```bash
    docker exec -it pg psql -U monitor -d clickstream -c "SELECT COUNT(*), SUM(is_anomaly::int) FROM window_results;"
    ```

    Expected output: `360 | 22`.

## Troubleshooting

| Problem | Cause | Fix |
|---|---|---|
| `No module named sqlalchemy` | The system-wide `streamlit` ran instead of the venv one | Use `python -m streamlit run dashboard.py` |
| `password authentication failed` | Password in `.env` does not match the one PostgreSQL was initialised with | Make sure `.env` matches `docker-compose.yml`. If you changed the password, recreate the container: `docker compose down -v && docker compose up -d` |
